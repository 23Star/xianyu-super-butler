# 上游功能迁移

本项目基于 `zhinianboke/xianyu-auto-reply` 二次开发，同时保留当前管理界面、SQLite 默认部署方式和单一 `8080` 应用入口。

## 迁移原则

- 按功能逐项比较，不直接覆盖当前代码。
- 已有功能以稳定性、安全性和实际体验为判断标准，选择性吸收更优实现。
- 新功能先完成本地数据模型、服务和测试，再接入真实闲鱼业务链路。
- 涉及支付、激活或第三方平台的能力保持可选，不成为基础功能的强依赖。
- Cookie、Token、卡密、订单隐私数据和日志不得进入版本库。

## 第二批通知与日志

- 支持钉钉、飞书、Bark、邮件、Webhook、企业微信和 Telegram 通知渠道。
- 支持通知渠道创建、编辑、启停、删除及账号绑定。
- 风控日志按当前用户的闲鱼账号归属隔离，并支持账号、处理状态和分页筛选。
- 系统运行日志仅管理员可见，支持按级别和来源查询。
- 通知配置不再输出到运行日志，Bark 设备密钥仅记录是否已配置。

## 第一批发货拦截规则

优先迁移能够由本地可靠数据判断的规则：

- 个人黑名单
- 当前账号已有其他订单
- 同一系统用户的其他账号已有订单
- 当前账号存在未确认收货订单

依赖闲鱼实时信用接口的规则暂缓接入真实发货流程，待接口行为和失败策略经过测试后再启用。
