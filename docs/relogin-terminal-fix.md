# 人工重登终态接线修复

## 范围

基于上游 `origin/main`（基点 `9b6ed01`）的独立通用修复，不包含私有维护分支改动、滑块轨迹调整、部署或服务重启。

## 行为

- 真实发起密码登录且未取得 Cookie（含浏览器调用异常）时累计一次失败；冷却跳过、未配置账密、任务取消不计失败。
- 连续三次失败进入 `needs_relogin` 人工终态，通知一次；成功登录或成功获取 Token 清除完整失败状态。
- 会话明确过期且没有可用账密时直接要求人工登录，不伪装成三次浏览器失败。
- 终态阻断自动密码登录和 Token 请求，主循环关闭连接并停止后台任务。30 分钟计时结束不会自动解除终态（方案 A）。
- 主循环不再通过重建实例清空尚未到阈值的失败计数，而是在同一实例中等待密码登录冷却后重试。
- 人工更新数据库 Cookie 后，停驻循环只读本地配置并重新加载 Cookie，清除终态，随后走正常连接验证。后台页面更新 Cookie/扫码的既有 CookieManager 替换任务链路继续有效。
- 终态与计数是实例内状态，不增加数据库 schema 或跨进程持久化。主动重启整个服务会重新初始化状态；本修复保证的是同一服务进程内的自动重试止损。

## 根因

上游终态辅助方法未被调用；失败计数缺初始化；连接失败时重建实例使连续计数无法累积；后台 Token 刷新仍发送“将自动重试”通知；原停驻函数没有识别人工更新 Cookie 的路径。

执行：

```bash

python -m py_compile XianyuAutoAsync.py tests/test_relogin_terminal.py tests/test_relogin_flag_lifecycle.py
git diff --check
```

结果：24 个测试通过（17 个新增真实方法行为测试 + 7 个原生命周期测试），语法和差异检查通过。

提交前复审补充：冷却/更新失败不误标人工终态，普通 Token 成功不清零 WebSocket 失败计数，周期 Cookie 刷新的在途子任务随父任务取消，迟到 Token 响应不解除新进入的人工终态。

新增测试从源码 AST 提取并执行原方法（不复制实现），只替换数据库、浏览器、网络等外部边界，避免导入生产模块时初始化真实数据库和日志；使用受控时钟验证超时不解除终态、人工更新 Cookie 解锁、任务取消不算登录失败、后台退出与主循环保留失败计数。

未做真实闲鱼登录、生产数据写入、前端构建、部署或重启；未运行含真实模块初始化副作用的全套上游测试。
